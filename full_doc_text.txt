Methodology
Research Design

The study will employ a mixed-methods research design, combining quantitative and qualitative approaches to evaluate the effectiveness of the SeeRuta application. The quantitative method will be used to measure the application's accuracy, task completion, and efficiency in discovering jeepney routes and recognizing jeepney codes. Meanwhile, the qualitative method will gather feedback from selected users regarding the application's usability, accessibility, and overall experience. 
Research Locale
The study will be conducted in Cebu City, Philippines, where the SeeRuta application will be developed and tested. The location is selected because of the city's extensive jeepney transportation system, which serves as a primary means of transportation for many commuters. The study will focus on selected jeepney routes and stops within the city to evaluate the application's offline route discovery and real-time jeepney code recognition features.
Research Participants / Respondents
	The study will involve selected commuters in Cebu City, particularly students, tourists, and persons with disabilities (PWDs), who will participate in evaluating the SeeRuta application. They will be asked to test its features and provide feedback regarding its accuracy, efficiency, usability, and accessibility. Their responses will help determine the application's effectiveness in assisting commuters with jeepney route discovery and code recognition.

Ha1. Overview

SeeRuta is an offline vector map application built with Flutter, designed to display detailed geographic information for Cebu City using locally stored MBTiles vector data. The application follows a modular architecture that separates concerns between the UI layer, map rendering engine, data access layer, and business logic. The system is designed to operate fully offline after initial asset deployment, making it suitable for environments with limited or no network connectivity.

4. Design Decisions

• MapLibre GL over flutter_map: Migrated from flutter_map to MapLibre GL for native GPU-accelerated vector tile rendering, providing smoother zooming and panning performance.
• Offline-first architecture: All map data (MBTiles) and glyphs are copied to app storage on first launch, enabling fully offline operation without network dependency.
• Layer-based visibility: Admin-controlled layer visibility via MapLibre's setLayerVisibility() API, allowing dynamic show/hide of vector tiles, boundary mask, user location, and direction arrow.
• Style separation: Map styling is defined separately in cebu_style.dart and regenerated on each launch via offline_map_assets.dart, allowing style changes without app reinstall.
• ValueNotifier pattern: Reactive UI state management using ValueNotifier and ValueListenableBuilder for layer toggles, telemetry, and style rebuild triggers.

5. Data Flow

1. App launch: HomePage._prepareMap() calls OfflineMapAssets.prepare(), which copies MBTiles and glyphs to app storage and generates style.json.
2. Map rendering: CebuMapView initializes MapLibre with the style, adds boundary mask and user location layers.
3. User interaction: Admin toggles in AdminPage update ValueNotifiers, which CebuMapView listens to and calls setLayerVisibility() accordingly.
4. Style rebuild: Admin "Rebuild map style" bumps a ValueNotifier in main.dart, triggering HomePage to re-call prepare().

8. Asset Pipeline

The MBTiles file (assets/maps/cebu_city.mbtiles, 41.3 MB) contains OpenMapTiles vector data for Cebu City (zoom levels 0–14, TMS scheme, gzip-compressed PBF). Glyph folders under assets/glyphs/ provide NotoSans fonts for map labels. On first launch, OfflineMapAssets.prepare() copies these to app storage and writes a MapLibre-compatible style.json.

2. Core Coding Patterns

a) ValueNotifier Pattern (Admin layer toggles)

    final ValueNotifier<bool> showVectorTiles = ValueNotifier<bool>(true);

    // In AdminPage — switch bound to notifier:
    SwitchListTile(
      value: widget.showVectorTiles.value,
      onChanged: (nv) => widget.showVectorTiles.value = nv,
    )

    // In CebuMapView — listening for changes:
    widget.showVectorTiles?.addListener(_onVisibilityChanged);
    // Calls MapLibre setLayerVisibility(layerId, visible)

b) MapLibre Layer Visibility

    await controller.setLayerVisibility(layerId, visible);

c) Style Rebuild Trigger (Admin → HomePage)

    // main.dart — Admin triggers rebuild:
    onRebuildStyle: () => _rebuildStyleKey.value++,

    // HomePage — listens for rebuild:
    widget.rebuildStyleKey.addListener(_onRebuildStyleKey);
    void _onRebuildStyleKey() { _prepareMap(); }

d) Location Service (ChangeNotifier pattern)

    class LocationService extends ChangeNotifier {
      LatLng? _position;
      double? _heading;
      double? _accuracyMeters;
      Future<void> enable() async { /* GPS + compass setup */ }
      void disable() { /* Stop streams */ }
    }

Ethical and Safety Considerations
The research will ensure the use of ethical and safety measures to protect those who will be involved in using the SeeRuta application. Participation will be voluntary, and the researchers will clearly communicate the aim of the study to the participants before gathering any data. Their data will be kept confidential and will be used for research only.

It will be also ensured by the researchers that the app provides accurate and understandable information about the routes and fare. Because of using the stored offline data, the users will be informed that there may be changes in routes and fare, and the information may not be up to date. Testing will be done in order to prevent provision of inaccurate or misleading instructions that can influence users while traveling.

Moreover, the researchers will consider the rights and safety of all the participants.
